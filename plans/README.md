# Implementation Plans

Generated by the `improve` planning workflow on 2026-07-24 and maintained
alongside the implementation. The detailed plan records its current
capability and test baseline.

This directory contains the long-range completion plan. It does not replace
`docs/design.md`, which describes the currently shipped implementation. Before
implementing a roadmap milestone, split that milestone into a small checkpoint
plan with exact file scope, tests, and a separate commit.

## Dependency notes

Plan 001 is a program roadmap, not one atomic change. Its milestones have their
own dependency graph:

```text
completion contract and coverage ledger
              |
              v
effective field operations and decision-oracle interfaces
          /                         \
         v                           v
structure/dependency solvers     algebraic-curve kernel
         |                           |
         v                           v
general RDE/PRDE engine          algebraic integration
         |                           |
         v                           |
complete transcendental cases       |
          \                         /
           v                       v
          mixed algebraic/transcendental towers
                         |
                         v
             automatic tower construction
                         |
                         v
              real/complex presentation
                         |
                         v
             completeness and upstream gates
```

The normalized P/E/T structural contract is implemented over `QQ(x)`, while
some recursive solver orderings retain explicit boundaries. The algebraic
track now has maximal orders, places, local expansions, and divisor arithmetic.
Plan 002 makes the narrow certified P/E/T admission boundary, including the
exact hyperbolic Möbius normalization exception at the active top level,
executable. Its public result vocabulary, declared-cell tests, documentation,
and CI gate are now in place. Plan 003 freezes the current certified P/E/T
source directions as explicit fundamental signatures while keeping the
Gaussian conversion as an independent check. Plan 004 now
provides a narrow constant-field decision and complete all-place data for its
admitted preserved presentations; an actual function-field presentation
rebase remains a later normalization task. Plan 005 established the global
Riemann--Roch service; the later Hess finite/infinite ideal-intersection route
now computes complete long bases for the direct models admitted by the
maximal-order layer. Plan 006 provides an independent exact finite-dimensional
valuation kernel and retains bounded nonspecial search only as an explicitly
incomplete auxiliary route.
Plan 007 adds a deliberately conservative one-variable expression compiler
for rational arithmetic and nested P/E/T calls. It reuses the certified tower
factories and returns local back-substituted presentations, while leaving
general algebraic/mixed discovery and branch-aware normalization open.
Plan 008 consumes two caller-supplied checked linear special factors to make a
quadratic/Riccati active top level explicitly hyperexponential. It preserves
the ordinary P/E/T admission boundary: no Riccati or Darboux factor search is
claimed, and only the transformed target is passed to the total dispatcher.
Plan 009 is a deliberately narrower consumer: it removes locally exact
principal parts at one supplied linear special factor by solving lower-field
RDEs. An unsolved local equation remains an explicit boundary rather than an
elementary-integration or non-elementarity conclusion.
Plan 010 adds exact `QQ`-coordinate expansion for native finite algebraic
constant fields at the standard rational base. It deliberately stops before
recursive general-constant towers, whose no-new-constants evidence must be
made proof-carrying rather than inherited from caller metadata.
Plans 011-013 complete the first exact divisor-torsion path over `QQ`, including
compatible displayed-constant composita and good-prime order bounds. Plan 014
uses that algebraic foundation at the expression boundary: it discovers
algebraic and P/E/T candidates as a dependency graph, constructs mixed towers
where the native domain backend permits them, and keeps successful structural
discovery separate from the set of integration backends implemented so far.
Plan 015 expands the algebraic path into its actual dependency program. The
current Hess ideal-intersection routine remains a complete Riemann--Roch
algorithm for the direct models it admits, but the full engine still needs
presentation normalization, total maximal-order arithmetic, Hess's parametric
and large-divisor algorithms, scalable class arithmetic, complete algebraic
integration, algebraic RDEs, and their relative mixed-tower forms. Plan 014's
remaining execution cells depend on those services rather than on more
syntax-directed special cases.
Plan 016 gives the transcendental track the same decomposition: effective
constants, recursive structure decisions, total P/E/T scalar, parametric, and
coupled RDEs, the optional general-monomial special-polynomial branch, and a
total explicit-tower dispatcher. Plan 017 then owns the remaining user-facing
work: automatic verified tower construction, reversible compilation,
complex-local and branch-aware real presentation, completeness evidence,
performance, and incremental SymPy upstreaming.

- Plan 016 T0-T2 supplies the effective-constant and structure decisions
  needed by its RDE and integration checkpoints.
- Plan 015 A0-A9 and Plan 016 T0-T8 may advance independently after their
  shared effective-field boundary is fixed.
- Plan 015 A10 joins the completed algebraic and transcendental tracks.
- Plans 014 and 015 A11 finish mixed discovery/execution; Plan 017 consumes
  those explicit algorithms for public construction and presentation.

## Findings considered and rejected

- Treating Bronstein's Chapter 7 heuristic as a complete dependency decision
  was rejected because Example 7.3.2 has a solution that the heuristic misses.
- Defining completion as support for every arbitrary SymPy constant or special
  function was rejected because the classical Risch algorithm assumes an
  effective constant field and applies to elementary extensions, not arbitrary
  identity problems or special functions.
- Rewriting the project around a private element hierarchy was rejected. The
  established design deliberately uses native SymPy domains and immutable tower
  metadata.
- Treating the current partial algebraic integrator as complete was rejected:
  its displayed-constant logarithmic slice still lacks compatible constant
  descent, complete divisor-class work, and second-kind exactness.
